# User Stories – Accessible Study Companion

## User Story 1 – Accessible Reading

**As a** university student,  
**I want** to adjust the text size and colour contrast when viewing study materials,  
**so that** I can read documents more comfortably and independently.

**Acceptance criteria:**
- Users can increase and decrease text size.
- Users can select different interface themes.
- Users can enable a high-contrast mode.
- Changes are applied immediately.
- Reading preferences can be saved.

## User Story 2 – Text-to-Speech

**As a** university student,  
**I want** to have study materials read aloud to me,  
**so that** I can access educational content without relying entirely on visual reading.

**Acceptance criteria:**
- Users can select a document or supported text.
- Users can start and stop audio playback.
- Users can pause and resume playback.
- Users can adjust reading speed.
- The application provides clear playback feedback.

## User Story 3 – Study Material Management

**As a** university student,  
**I want** to upload and organise my study materials,  
**so that** I can easily find and access my educational resources.

**Acceptance criteria:**
- Users can upload supported documents.
- Users can view their saved documents.
- Users can organise documents into categories.
- Users can search for documents.
- Users can delete documents they no longer need.

# User Journey – Accessible Reading

**Goal:** John wants to open a study document and adjust its appearance to make it easier to read.

1. **Open application:** John launches the Accessible Study Companion and accesses his personal library.
2. **Select document:** John selects an existing study document or uploads a new one.
3. **Adjust accessibility settings:** John increases the text size and selects a suitable contrast theme.
4. **Access study material:** John reads the document or activates text-to-speech to listen to its contents.
5. **Save preferences:** The application saves his accessibility settings so they can be restored during future sessions.

---

# UI Interaction Patterns

The application will use the following interaction patterns:

| Interaction | Purpose |
|---|---|
| Sidebar navigation | Navigate between the library, reader and settings |
| Buttons | Perform actions such as uploading documents and starting audio |
| Sliders | Adjust text size and reading speed |
| Toggle switches | Enable or disable accessibility features |
| Dropdown menus | Select themes and document categories |
| File selection dialogs | Upload study materials |
| Search fields | Find specific documents |
| Audio controls | Play, pause, resume and stop text-to-speech |
| Confirmation dialogs | Confirm actions such as deleting documents |
| Keyboard navigation | Allow users to navigate without relying on a mouse |

The interface will prioritise accessibility through readable text, clear navigation, consistent layouts and customisable appearance settings.

---

# Personalisation

The application will allow users to customise their reading experience.

Planned options include:

- Adjustable text size.
- Light and dark themes.
- High-contrast mode.
- Customisable accent colours.
- Adjustable text-to-speech speed.

These preferences will be saved so users do not need to configure their accessibility settings every time they open the application.

# Wireframe – Accessible Reading Interface

**User story:** Accessible Reading.

The reading interface will contain:

1. A navigation sidebar for accessing the document library and settings.
2. A document viewing area displaying the selected study material.
3. Text size adjustment controls.
4. A theme selection control.
5. A high-contrast toggle.
6. Text-to-speech playback controls.

**User journey:**

Open application → Select document → Adjust reading settings → Read or listen to document → Save preferences.

A visual wireframe will be created separately to demonstrate the proposed layout and placement of these interface elements.

---

# Design Considerations

- Accessibility settings should be easy to locate.
- Users should be able to customise the interface to their preferences.
- The application should provide clear feedback when performing actions.
- Important information should not be communicated through colour alone.
- Keyboard navigation should be supported.
- The application should avoid unnecessary interface complexity.
- Accessibility preferences should persist between sessions.
